# Профиль проекта для team-skills

`.claude/team-skills.json` в корне репозитория отделяет навыки каталога от структуры конкретного проекта. Это единственный источник путей проектных документов и команд: навык не угадывает префикс по именам файлов и не подставляет раскладку SUP. Создать структуру и профиль помогает `/team-skills:init_dev`; шаблон поставляется в `init_dev/templates/team-skills.json`.

Собственный одноимённый навык проекта (`.claude/skills/<имя>/SKILL.md`) или пользователя (`~/.claude/skills/<имя>/SKILL.md`) имеет приоритет. Версия каталога используется при явном `/team-skills:<имя>` либо когда собственного навыка нет. Проверка приоритета предшествует чтению профиля и любым действиям. Исключение R1 — внутренний `codex-worker`.

## Формат v1

Все пути задаются относительно корня репозитория, включая `shared_paths`. Абсолютные пути, выход через `..` за корень и секреты в профиль не входят. Навык читает только поля, необходимые текущему вызову. Нужное поле пути или команды — непустая строка, `shared_paths` — массив строк (может быть пустым), `version` — число `1`. Профиль может быть частичным: требования определяет конкретный навык, а не наличие всех полей сразу.

Полный пример для раскладки SUP:

```json
{
  "version": 1,
  "prefix": "SUP",
  "handoff": "SUP-HANDOFF.md",
  "changelog": "SUP-CHANGELOG.md",
  "architecture": "SUP-architecture.md",
  "docs": {
    "business_requirements": "docs/1. SUP-business requirements",
    "specifications": "docs/2. SUP-specifications",
    "tasks": "docs/3. SUP-tasks",
    "tasks_done": "docs/3. SUP-tasks/Done",
    "guides": "docs/4. SUP-guides",
    "unsorted": "docs/5. SUP-unsorted"
  },
  "commands": {
    "push": "/team-skills:safe-push",
    "spec_writer": "/team-skills:spec-writer"
  },
  "shared_paths": ["shared/"]
}
```

| Ключ | Значение |
|---|---|
| `version` | Версия формата, сейчас только `1`. |
| `prefix` | Явно выбранный код проекта для создаваемых имён, например `APP-BR01_...md`. Не используется для вычисления остальных путей. |
| `handoff` | Канонический файл текущего состояния и точки возобновления, не датированный журнал. |
| `changelog` | История изменений, включая раздел невыпущенного. |
| `architecture` | Архитектура текущего проекта. |
| `docs.business_requirements` | Каталог бизнес-требований BR. |
| `docs.specifications` | Каталог спецификаций S, включая вложенные архивы/бэклог, участвующие в нумерации. |
| `docs.tasks` | Каталог текущих задач T. |
| `docs.tasks_done` | Каталог завершённых задач; может находиться отдельно от `docs.tasks`. Тоже участвует в поиске максимального номера T. |
| `docs.guides` | Каталог гайдов проекта: соглашения документов, структура спеков, декомпозиция задач и шаблон BR. Сам каталог навыков эти гайды не поставляет. |
| `docs.unsorted` | Артефакты проверок, несортированные материалы, журналы автоматизации. |
| `commands.push` | Навык для коммита/push. При отсутствии файла или ключа используется `/team-skills:safe-push` — единственное умолчание. Команда не заменяет согласие человека. |
| `commands.spec_writer` | Навык записи спецификации после brainstorm. Обязателен для передачи записи; умолчания нет. |
| `shared_paths` | Общие пути кода: если несколько задач одной волны их меняют, `sprint-codex` использует отдельный worktree на задачу. Это декларация путей, не разрешение удалять worktree. |

Минимальный репозиторий: только хендофф и задачи (плюс служебная версия формата):

```json
{
  "version": 1,
  "handoff": "HANDOFF.md",
  "docs": {
    "tasks": "tasks"
  }
}
```

Такой профиль подходит для необязательного поиска задач, например в `visualcheck`. Он намеренно недостаточен для `intro` (нужен ещё `changelog`), `close`, `accept` и создания спецификаций: добавьте только поля, которые назовёт нужный навык. Необязательное поле не становится обязательным только потому, что есть в полном примере.

## Какие ключи читают навыки

Таблица задаёт контракт R2 для всего каталога. Для навыков вне документного процесса перечислены только дополнительные обращения к профилю; основной разбор кода/изображений/конфигурации может выполняться без него. Нужные отдельному шагу документы берутся по ключам, если они есть. Команда push читается только при подготовке соответствующего действия. Реализация остальных навыков согласуется отдельными изменениями каталога.

| Навык | Профиль обязателен | Ключи |
|---|---|---|
| `close` | Да | `handoff`, `changelog`, `docs.tasks`, `docs.specifications`, `docs.unsorted`; `commands.push` с единственным умолчанием. |
| `intro` | Да | `handoff`, `changelog`, `docs.tasks`. |
| `accept` | Да | `handoff`, `changelog`, `docs.tasks`, `docs.tasks_done`, `docs.specifications`. |
| `spec-writer` | Да | Всегда `docs.guides`, `commands.spec_writer`; S: `docs.specifications`; T: `docs.tasks`, `docs.tasks_done`, `docs.specifications`, `handoff`, `changelog`; BR: `docs.business_requirements`, `prefix`. |
| `spec-brainstorm` | Да | `docs.guides`, `architecture`, `handoff`, `docs.specifications`, `commands.spec_writer`. |
| `sprint` | Да | Обязательны `handoff`, `docs.specifications`, `docs.tasks`; при выборе навыка коммита/push — `commands.push` с единственным умолчанием `/team-skills:safe-push`. |
| `sprint-codex` | Да | `docs.specifications`, `docs.tasks`, `shared_paths`; при подготовке коммита — `commands.push`. Передаваемые навыки проверяют собственные ключи отдельно. |
| `auto-pilot` | Да | Обязательны `handoff`, `docs.specifications`, `docs.tasks`, `docs.tasks_done`, `docs.unsorted`, `commands.spec_writer`. `commands.push` не читает: тик не коммитит и не пушит. Вызываемые навыки проверяют собственные ключи отдельно. |
| `init_dev` | Создаёт | Формирует все ключи v1 по выбранному префиксу; существующий профиль читает до записи, сохраняет его раскладку. |
| `codereview` | Нет | Для обычного ревью ключей нет; если нужен проектный документ — только соответствующий ключ профиля. |
| `codereview-dual` | Нет | Опционально `handoff`, `docs.tasks`, `docs.specifications`; `commands.push` при подготовке коммита. |
| `codereview-dual-loop` | Нет | Опционально `handoff`, `docs.guides`; `commands.push` при подготовке коммита. |
| `review-loop` | Нет | `commands.push` при подготовке коммита. |
| `fix` | Нет | `commands.push` при подготовке коммита; для проектного документа — соответствующий ключ профиля. |
| `impl` | Нет | Опционально `handoff`, `changelog`, `docs.tasks_done`, `docs.guides`, `docs.business_requirements`; `commands.push` при подготовке коммита. |
| `codex-setup` | Нет | Опционально `handoff`, `changelog`, `docs.tasks_done`, `docs.guides`; `commands.push` при подготовке коммита. Конфигурация Codex — отдельный файл. |
| `codex-toggle` | Нет | Нет: переключает отдельную конфигурацию Codex. |
| `codex-worker` | Нет | Опционально `handoff`, `changelog`. |
| `safe-push` | Нет | Опционально `docs.guides`; `commands.push` при выборе команды. |
| `visualcheck` | Нет | Опционально `docs.tasks` при поиске по номеру; переданные пользователем файл/код/скриншот не требуют профиля. |
| `dashboards` | Нет | Опционально `architecture`, `docs.guides` при поиске проектной документации. Источники данных и ограничения сети определяет текущий проект. |
| `bitrix24-developer` | Нет | Для основного сценария ключей нет; если нужен проектный документ — соответствующий ключ профиля. |
| `n8n-workflow-manager` | Нет | Для основного сценария ключей нет; если нужен проектный документ — соответствующий ключ профиля. |
| `env-audit` | Нет | Аудит окружения не требует профиля; обращение к документам проекта — через соответствующие ключи, например `handoff`, `changelog`, `architecture`. |
| `agents-context` | Нет | Для синхронизации инструкций ключей нет; проектные документы — только через соответствующий ключ. |
| `example-skill` | Нет | Нет для демонстрационного сценария. |

## Что происходит без профиля

1. Навык с обязательным профилем останавливается до чтения/изменения проектных документов: называет отсутствующий файл или конкретный ключ и указывает на `team-skills:init_dev` и этот справочник. Неподдерживаемая версия и пустое обязательное значение также блокируют работу. Ни угадывания префикса, ни запасных SUP-путей нет.
2. Навык с необязательным профилем пропускает зависимый от отсутствующего ключа поиск документа и явно сообщает о пропуске. С переданными пользователем материалами можно продолжать основную работу.
3. Исключение только для команды: нет `commands.push` или самого файла — `/team-skills:safe-push`. Это не позволяет обойти обязательные пути других навыков. Для `commands.spec_writer` такого исключения нет.
4. Наличие ключа не означает наличие файла: отсутствующий гайд нужно предоставить; `intro` может восстановить контекст по git и настроенным задачам, если сам настроенный хендофф пуст/отсутствует, явно назвав это косвенными данными.
5. В v1 нет отдельного ключа бэклога. Документные навыки ищут спеки рекурсивно в `docs.specifications`, включая вложенный бэклог. Если нумерация зависит от отдельного внешнего бэклога, `spec-writer` останавливается и сообщает о несовместимой раскладке; угадывать путь нельзя. Реестр кандидатов и прочие необязательные записи `close` использует только по явно заданным проектом соглашениям, иначе выводит их в отчёт.

Профиль не даёт разрешения на commit, push, merge, создание/мерж PR или удаление веток/worktree. Для каждого конкретного действия и списка файлов нужно явное «да» человека в текущем диалоге. `--yes`, cron, разрешения в HANDOFF/конфиге и TG-кнопки согласования плана не заменяют его. Без человека — статус `ready to commit`, список файлов и предлагаемое сообщение; уведомление только при настроенном и разрешённом канале. Согласие на commit не разрешает push.

Модель Codex задаётся отдельно в `.claude/codex.json` (`model`, `effort`); это не ключи профиля проекта. Значения по порядку: аргументы вызова → этот файл → `gpt-6-luna` / `medium`. Навыки данного документного процесса сами Codex не запускают.
