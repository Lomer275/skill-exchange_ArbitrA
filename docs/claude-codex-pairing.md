# Связка Claude × Codex: «Claude думает — Codex программирует» (портируемая версия)

> **Что это.** Режим работы, при котором дорогая думающая модель (Claude Code) перестаёт быть
> машинисткой: она находит код, выбирает подход и пишет бриф, а весь исполняемый код печатает
> Codex. Claude потом читает дифф и гоняет тесты. Роли не пересекаются.
>
> **Как установить (агенту достаточно этого файла):**
> 1. Прочитай раздел «Предпосылки» и проверь, что Codex CLI стоит и авторизован.
> 2. Забери три навыка из каталога команды: `impl`, `codex-worker`, `fix`
>    (`scripts/skill_sync.sh pull <имя>` или вручную из `plugins/team-skills/skills/`).
> 3. Пройди по маркерам `[АДАПТИРУЙ]` — подставь пути и границы своего проекта (~10 минут).
> 4. Скажи агенту «поправь X» — дальше он делегирует сам.
>
> **Зачем.** Думающая модель, которая сама печатает код, тратит дорогой контекст на механику
> и втягивается в правку вместо проектирования. Разделение даёт: дешевле реализация, честное
> ревью (дифф читает не тот, кто его писал), параллелизм (N воркеров), и — главное — Claude
> вынужден формулировать задачу явно, а не «понимать её по ходу».

---

## Предпосылки

| Что | Проверка | Если нет |
|---|---|---|
| Codex CLI ≥ 0.143.0 | `codex --version` | `npm i -g @openai/codex@latest` |
| Авторизация | `codex exec --skip-git-repo-check "ok"` | `codex login` (ChatGPT-подписка) |
| Движок-компаньон (желательно) | `ls ~/.claude/plugins/cache/openai-codex/codex/*/scripts/codex-companion.mjs` | работает и без него — `codex-worker` откатится на legacy `codex exec` |

**Версия 0.143.0 — не каприз.** До неё параллельные воркеры гоняют общий `auth.json` и
периодически падают с `refresh_token_reused (401)` (openai/codex#10332). В 0.143.0 добавлен
кросс-процессный `refresh.lock`.

**Все воркеры обязаны делить ОДИН `CODEX_HOME`** (дефолт `~/.codex`). Не изолируй его
по воркеру/worktree: каждый home поднимает свой демон со своей копией того же
одноразового refresh-токена → гонка. Изоляция файлов делается через `--cwd`, и только.

## Что установить

### 1. Kill-switch — `.claude/codex.json`

```json
{
  "enabled": true,
  "disabled_reason": null,
  "cli_version": "codex-cli 0.143.0",
  "cli_flags": {
    "output_last_message": "--output-last-message",
    "skip_git_repo_check": "--skip-git-repo-check"
  },
  "availability_cache": { "checked_at": null, "available": null, "reason": null }
}
```

Precedence: переменная окружения `SUP_CODEX_ENABLED` со значением `true/1/yes` или `false/0/no`
перебивает файл; любое другое значение — игнорируется, читается файл.
`[АДАПТИРУЙ: имя env-переменной под свой проект, если `SUP_` не ваш префикс]`

**Зачем kill-switch:** Codex ложится (auth, лимиты, сеть) — одним тумблером возвращаешься
к обычной работе, не переписывая навыки.

### 2. `AGENTS.md` в корне репо — Codex читает его автоматически

Обязательные блоки:

```markdown
## Разделение труда

Claude думает и решает. Ты программируешь.

- Весь исполняемый код пишешь ты: [АДАПТИРУЙ: *.py, tests/, *.sql, *.sh, *.js — расширения вашего стека].
- Доки, спеки, конфиги, CHANGELOG — не твои, их ведёт оркестратор. Разошлись с кодом — скажи, не правь.
- Тебе приходит бриф: подход уже выбран. Реализуй его, а не проектируй заново.
- Бриф неверен → сделай как написано, насколько возможно, и явно опиши расхождение в финальном сообщении.
- Дифф читают против брифа. Расширение скоупа и попутный рефакторинг будут откачены.

## Запреты

1. Никаких `git commit` / `git push` без прямой команды.
2. Не трогать секреты: [АДАПТИРУЙ: .env*, .servers, ваши файлы кредов].
3. Не править [АДАПТИРУЙ: CHANGELOG.md, HANDOFF.md, папку завершённых задач].
4. Не спавнить других воркеров — оркестрацию ведёт только Claude.
5. [АДАПТИРУЙ: python из $VIRTUAL_ENV/bin/python и прочие правила запуска вашего стека].
```

### 3. Навык `codex-worker` — рантайм (забрать из каталога)

Внутренний хелпер, пользователь его не зовёт. Контракт:

```
Skill(codex-worker, "role=implementer brief_file=<путь> scope=edit:<файлы> task_id=<slug> timeout_min=15")
→ status: ok|timeout|disabled|error, output_file: <путь>, task_id, duration_s
```

Что делает: проверяет kill-switch → находит движок → собирает промпт-файл → запускает
в фоне → watchdog по таймауту → возвращает финальное сообщение Codex файлом.

`role=reviewer` — read-only, для второй линзы на ревью. `role=implementer` — с правом записи.

### 4. Навык `impl` — точка входа (забрать из каталога)

Пять шагов: routing-проверки → **Claude думает** → бриф → делегирование → **Claude ревьюит дифф**.
Шаг «Claude думает» — обязательный; без него делегирование вырождается в пересказ запроса воркеру.

### 5. Правило в `CLAUDE.md` проекта

```markdown
## Разделение труда Claude × Codex

> Claude думает и решает. Codex программирует.

Claude не пишет исполняемый код ([АДАПТИРУЙ: список расширений]). Находит код, выбирает подход,
пишет бриф, отдаёт /impl → Codex реализует → Claude читает дифф и гоняет тесты.
[АДАПТИРУЙ: доки/спеки/конфиги/память] остаются за Claude — это и есть «думает и решает».

Карман исключений (объявлять вслух одной строкой): Codex недоступен · правка ≤3 строк
в открытом файле · Codex дважды промахнулся · нужен диалог по ходу · пользователь сказал «сам».
```

Без этой строки в `CLAUDE.md` режим не включится: навык существует, но агент про него не вспомнит.

## Анатомия брифа (то, ради чего всё)

Плохой бриф — единственная реальная причина, по которой связка не работает.

```markdown
# ЗАДАЧА
<одно предложение: что должно измениться в ПОВЕДЕНИИ системы>

# КОНТЕКСТ
<почему; какой баг/фича; что уже выяснил оркестратор — путь, виновная строка, механизм>

# ЧТО СДЕЛАТЬ
1. <шаг с указанием файла и функции>

# ГРАНИЦЫ
Правь ТОЛЬКО: <file1, file2>
НЕ трогай: <всё остальное; рефакторинг вне задачи; переименования>

# КРАЙНИЕ СЛУЧАИ
- <пустое значение / ошибка сети / выключенный флаг>

# DoD
- <проверяемый критерий: тест X зелёный / команда Y печатает Z>
- Существующие тесты не сломаны.
```

**Планка качества:** по этому брифу должен отработать инженер, не видевший вашего диалога.
Не проходит планку — значит оркестратор сам не разобрался в задаче, и делегировать рано.

## Карман исключений (иначе режим станет догмой и будет мешать)

1. Codex недоступен / kill-switch выключен → Claude пишет сам, работа не встаёт.
2. Правка ≤3 строк в файле, уже открытом в сессии, без проектного содержания.
3. Codex дважды промахнулся мимо брифа на одной правке → Claude доделывает. Не зацикливаться.
4. Правка требует живого диалога с пользователем по ходу.
5. Пользователь сказал явно: «сделай сам», «без кодекса».

Каждое применение — вслух одной строкой, с причиной. Молчаливое исключение = режима нет.

## Грабли, проверенные в бою

| Грабля | Что происходит | Лечение |
|---|---|---|
| Отдали воркеру пересказ запроса вместо брифа | Codex проектирует сам и промахивается; выглядит как «Codex тупой» | Планка качества брифа; промах = дефект брифа, а не воркера |
| Изолировали `CODEX_HOME` по worktree | Плавающие `refresh_token_reused (401)` под параллелью | Один общий home; изоляция только через `--cwd` |
| Поверили полю `touchedFiles` от компаньона | Пустое даже при реальной записи → «воркер ничего не сделал» | Определять изменённые файлы через `git` |
| Приняли `status: ok` за «сделано верно» | Скоуп-крип и попутный рефакторинг уезжают в коммит | Читать `git diff` против брифа руками, всегда |
| Два воркера на один файл параллельно | Затирают друг друга | Пересекающиеся файлы — строго последовательно |
| Включили review-gate плагина Codex на `Stop` | Ревью на каждую остановку, дубль вашего цикла ревью, расход токенов | Держать gate выключенным |

## Как понять, что режим действительно работает

Не по ощущениям — по счёту в конце дня (см. навык `/close`, фаза «карточка эффективности»):

- сколько правок исполняемого кода ушло Codex'у;
- сколько Claude сделал сам и **по какому именно пункту** кармана исключений;
- правки без основания = нарушение режима, называть прямо.

Если «сам» стабильно больше половины и без причин — режим не внедрён, он просто записан.
