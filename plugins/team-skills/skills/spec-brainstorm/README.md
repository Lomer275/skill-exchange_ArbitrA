# Spec Brainstorm

Помогает сформулировать новую спецификацию через вопросы: проблема, цель, архитектура, риски и DoD. Требует профиль .claude/team-skills.json; финальную запись делегирует команде commands.spec_writer после подтверждения черновика человеком.

## Когда использовать

Когда у тебя сырая идея для новой спеки и хочется проверить через question-answer что она зрелая, прежде чем оформлять файл. См. полный `description` в [SKILL.md](SKILL.md) — там перечислены триггер-фразы.

## Что делает

См. [SKILL.md](SKILL.md) — 6 фаз (проблема → цель → архитектура → DoD → финализация → делегирование в команду из `commands.spec_writer`).

## Чем отличается от spec-writer

| | spec-brainstorm | spec-writer |
|---|---|---|
| Mode | Интерактивный (AskUserQuestion) | Генеративный (по входному описанию) |
| Когда | Новая идея, нет структуры | Структура понятна, нужно оформить |
| Output | Финальный draft через делегирование | Файл по конвенциям |

Связка: brainstorm → собрал summary → передал в writer → файл готов в каталоге из `docs.specifications`.

Собственный одноимённый навык проекта или пользователя имеет приоритет. Для явного выбора версии каталога используйте `/team-skills:spec-brainstorm`.

Без профиля или необходимых ключей выполнение останавливается. Формат: [профиль проекта](../../../../docs/team-skills-profile.md); создать его помогает `/team-skills:init_dev`.
