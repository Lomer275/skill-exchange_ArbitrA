# Задачи GitHub — github-task

## Что делает

Помогает агенту вести issue от постановки до приёмки: создать, показать статус,
взять в работу, передать, сдать на проверку, вернуть с замечаниями, закрыть или
переоткрыть. Один ответственный, проверяющий отдельно, результат с доказательствами.

Работает с Claude Code и Codex. Репозиторий, доска, статусы, метки, порядок
закрытия и разрешения берутся из актуальных инструкций проекта. В скилле нет
внутренних адресов, персональных назначений и встроенного разрешения на записи.
Если профиль неясен, агент сначала уточняет его. Сам скилл не пишет код,
не делает мерж/выкат и не синхронизирует задачи с другими системами.

Версия скилла — **1.1.0**. Перед работой агент проверяет учётку человека и scopes
токена: `read:project` для чтения доски, `project` для записи. При нехватке прав
человек выполняет `gh auth refresh -h github.com -s project` и подтверждает код.
Агент не переключает общую активную учётку и не использует чужую.

Передача полуготовой ветки включает запушенную ветку, черновой PR с паспортом,
комментарий issue и одного согласованного нового Assignee. Получатель продолжает
ту же ветку через pull без force-push, читает паспорт и указанные файлы.
Паспорт обновляется в конце каждой сессии. Push/PR требуют разрешений целевого
проекта; иначе агент готовит паспорт человеку. Имя ветки задаёт проект;
при отсутствии правила агент предлагает `<type>/<issue>-<slug>`
(`feat`, `fix`, `docs`, `chore`). Рецепт и шаблон — в
[references/gh-operations.md](references/gh-operations.md).

## Установка

**Через marketplace:**

```
/plugin marketplace add Lomer275/skill-exchange_ArbitrA
/plugin install team-skills@skill-exchange
```

Доступ как `/team-skills:github-task`.

Если плагин уже установлен: `/plugin update team-skills@skill-exchange`.
После обновления проверить доступность команды; при необходимости перезапустить
Claude Code. Версия плагина с этим скиллом — **2.3.0** или новее.

**Через CLI (личная установка):**

```bash
python3 cli/skill_exchange.py install github-task
```

Доступ как `/github-task`.

Команда выполняется из свежей копии обменника. **CLI перезаписывает существующую
папку скилла:** прежде чем обновлять локально изменённую версию, прочитать diff и
сохранить свою копию. Не устанавливать поверх неизвестного содержимого.

**Для Codex:** попросить `$skill-installer` установить скилл из
`Lomer275/skill-exchange_ArbitrA`, путь `plugins/team-skills/skills/github-task`.
Установщик не должен перезаписывать уже существующий скилл без отдельного решения.
Вызов после установки — `$github-task`.

## Использование

Примеры запросов после указания проекта:

- «Покажи мои открытые issues и следующие шаги».
- «Создай issue: цель …, ответственный …, критерии …».
- «Возьми issue по этой ссылке в работу».
- «Сдай эту issue на проверку указанному проверяющему».
- «Верни с замечаниями» / «Закрой после подтверждённой приёмки».

Для безопасной первой проверки сначала запросить **только статус** существующей
issue. Затем, по согласованию, создать одну учебную issue и пройти создание,
автодобавление, смену статуса, проверку другим участником и закрытие. Не трогать
клиентские данные и секреты; тестовую issue не удалять, а закрыть после проверки.

Проверка синтаксиса и тесты на подставных ответах API не заменяют этот личный прогон.

## Если что-то не так

Не обходить отказ и не повторять создание вслепую. Написать в согласованную
внутреннюю issue или автору: ссылка на задачу, агент (Claude/Codex), шаг/команда,
ожидалось, получилось, безопасный текст ошибки или скриншот. Без токенов и
персональных данных. Вопросы и непонятные формулировки — тоже повод сообщить.

Обменник публичный: не переносить в его issues внутренние ссылки, логи и данные
проекта без разрешения. Обобщённую ошибку можно обсудить там отдельно.
