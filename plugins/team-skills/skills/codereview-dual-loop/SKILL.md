# /codereview-dual-loop — Цикл двойного ревью до чистоты

Связка `/codereview-dual` + `/review-loop` в одном явном вызове. На каждой итерации — параллельный двойной ревью (Claude + Codex), фикс только CRITICAL/HIGH в быстром режиме, повтор до чистоты или лимита.

**Старые скиллы НЕ заменяет** — `/codereview-dual` и `/review-loop` остаются доступны как отдельные команды.

---

## Входные данные

- `/codereview-dual-loop` — задача определяется автоматически из `*HANDOFF.md` (первая 🟡).
- `/codereview-dual-loop T17` — явный номер задачи.

Если ничего не передано и в HANDOFF нет 🟡 — попроси у пользователя.

---

## Критерий остановки

**Стоп:** `CRITICAL == 0 AND HIGH == 0`. MEDIUM и LOW не блокируют завершение.

## Лимит безопасности

Максимум **5 итераций**. После 5-й — прерываемся с предупреждением и списком оставшихся блокеров.

---

## Алгоритм

### Шаг 0 — Routing checks (kill-switch + availability)

Те же что в `/codereview-dual` (Шаг 0):

1. **Kill-switch.** Прочитай `.claude/codex.json:enabled` + env `CODEX_ENABLED` (precedence matrix из CLAUDE.md). Если выключен — graceful fallback: предупреди пользователя и делегируй в обычный `/review-loop`:

   ```
   ⚠️ Codex отключён. Делаю одиночный /review-loop (только Claude).
   Включить связку — /codex-toggle on.
   ```

   STOP здесь, передав управление `/review-loop`.

2. **Availability cache.** Свежая проверка если кэш устарел (TTL 1 час). При `available=false` — тот же fallback, что выше.

При обоих ✅ — продолжаем dual-loop.

---

### Шаг 1 — Старт

Сообщи пользователю:

```
## /codereview-dual-loop — Старт

Задача: T<NN> — <название>
Режим: dual (Claude + Codex параллельно) × итерации до чистоты
Стоп-критерий: CRITICAL == 0 AND HIGH == 0
Максимум итераций: 5
Фиксы: быстрый режим (без подтверждения), только CRITICAL и HIGH
```

---

### Шаг 2 — Итерация (повторять до стоп-критерия или лимита)

#### 2.1 — Запустить `/codereview-dual` напрямую

**ВАЖНО:** зовём именно `/codereview-dual`, **не** `/codereview` через роутинг. Это и есть смысл данного скилла — принудительный dual без роутинговой развилки.

```
Skill(skill="codereview-dual", args="T<NN>")
```

Получи таблицу findings с колонкой «Источник» (`[both]`/`[claude]`/`[codex]`).

#### 2.2 — Подсчитать CRITICAL и HIGH

Из таблицы:
- `CRITICAL` — количество находок этой severity.
- `HIGH` — количество находок этой severity.
- Дополнительно: `[both]`, `[claude]`, `[codex]`, `[severity-disputed]`.

Промежуточный статус:

```
### Итерация N — Результат dual-ревью
CRITICAL: X | HIGH: Y | MEDIUM: Z | LOW: W
Источники: [both]: A | [claude]: B | [codex]: C
Расхождения severity: D [severity-disputed]
```

#### 2.3 — Проверить критерий остановки

- **Если `CRITICAL == 0 AND HIGH == 0`** → Шаг 3 (успех).
- **Если итерация == 5 И есть CRITICAL/HIGH** → Шаг 4 (лимит исчерпан).
- **Иначе** → 2.4.

#### 2.4 — Запустить `/fix` в быстром режиме (только CRITICAL и HIGH)

Те же ограничения что в `/review-loop`:

- **Только CRITICAL и HIGH** — MEDIUM и LOW игнорируются.
- **Быстрый режим** — план показать, подтверждения не ждать, сразу выполнять.
- **Порядок:** CRITICAL → HIGH.

```
Skill(skill="fix", args="T<NN> --fast --severity=CRITICAL,HIGH")
```

После завершения фиксов — вернуться к Шагу 2 (следующая итерация).

## Правила

- **Сначала routing-проверка.** При выключенном/недоступном Codex — graceful fallback в обычный `/review-loop` (а не падение).
- **Принудительный dual каждую итерацию.** Зовём `/codereview-dual` напрямую — это смысл скилла.
- **Фиксить только CRITICAL и HIGH** — MEDIUM/LOW не трогать.
- **Быстрый режим обязателен** — план показать, подтверждения не ждать.
- **Считать итерации строго** — итерация = один полный `codereview-dual + fix`.
- **Если после ревью CRITICAL/HIGH == 0** — сразу финальный отчёт, без лишнего fix-прогона.
- **Лимит 5 итераций — жёсткий**, не превышать даже по просьбе.
- **Не пиши git commit/push** — это `/safe-push`.
- **Не вызывай этот скилл из `/sprint-codex`** — там по правилу правилу R5 спринт зовёт `/review-loop`, чтобы избежать двойного dual-ревью. Этот скилл — для ручного использования пользователем.
