# write-emulator

Скилл для написания эмуляторов внешних сервисов в unit-тестах — по паттернам,
уже принятым в команде (эмуляторы КадАрбитра, БФЛ+, Руспрофайла в ARP).

## Зачем

Внешние сервисы (HTTP API, HTML-страницы, CLI-бинари) в unit-тестах не зовутся
никогда. Вместо сети — DI-фейки: клиент принимает `axios`/`api`/`deps`
параметром, тест подсовывает фейк с канированными ответами. Скилл ведёт агента
по выбору правильного паттерна и обязательному набору сценариев, чтобы новый
эмулятор был устроен так же, как существующие.

## Что внутри

- Таблица выбора из 4 паттернов: `fakeAxios` (HTML-скрейпинг), `makeAxios`
  (REST + журнал вызовов), `makeApi`/`makeDeps` (фейк клиента целиком),
  mock-скрипт с ENV-режимами (CLI-подпроцессы) — с готовыми шаблонами кода.
- Правила канированных данных (брать из реальных ответов, чистить PII).
- Обязательные 5 групп сценариев: happy path, «не найдено», 401/5xx → типизированные
  ошибки, мусор на выходе, доменные кейсы (ambiguous / legacy stub / таймаут).
- Definition of done с требованием показать зелёный прогон тестов.

## Установка

```bash
python cli/skill_exchange.py install write-emulator
```

Или через маркетплейс — тогда скилл доступен как `/team-skills:write-emulator`.

## Использование

Скилл активируется сам, когда просишь «напиши эмулятор …», «замокай сервис для
тестов», «сделай фейк внешнего API», либо вручную:

```
/write-emulator
```

Эталонные реализации, на которые ссылается скилл, лежат в репо ARP
(multi-agent-app): `backend/tests/rusprofile-client.test.js`,
`backend/tests/bfl-plus-api-client.test.js`, `backend/tests/bfl-plus-sync.test.js`,
`backend/tests/fixtures/mock-claude.sh`.
