# Секреты и доступы — как читать раздел `secrets`

Правило раздела: **ты ищешь места и количества, а не значения**. Коллектор сам не выводит
ни значений, ни их фрагментов, ни хэшей; твоя часть — не вернуть их обратно в текст.

## Что уже посчитано

`sections.secrets` собран одним движком по одному набору классов: вебхуки Битрикса
(`/rest/<id>/<token>`, `rest/<id>/<token>` без ведущего слеша и голое `<id>/<token>` —
последнее только если в той же строке есть `bitrix`, `webhook` или `вебхук`), присваивания `api[_-]?key`, приватные ключи
(`-----BEGIN … PRIVATE KEY`), basic-auth URL, обобщённые присваивания, JWT, токены ботов,
ключи OpenAI и Anthropic, токены GitHub.

| Поле | Что означает |
|---|---|
| `context_files[]` | файлы, которые агент читает каждой сессией (глобальные правила, `CLAUDE.md`, `AGENTS.md`, память, скиллы): `path`, `kind` и `classes` с числом совпадений, различных значений и `user_ids` |
| `roots` | по каждому корню проекта: совпадения в **трекаемых git** файлах и в рабочем дереве, по классам, с первыми путями для инструкции по ротации |
| `home` | обход дома: `files_scanned`, `files_with_matches`, `by_class`, `excluded` (облачные каталоги), `truncated`, `stopped_at`, `not_reached` — каталоги верхнего уровня, до которых обход не дошёл. Первыми идут `.claude`, `.codex`, `.secrets`, `.ssh`, `.config`, `Desktop`, `Downloads`, `Documents`, `Tools` |
| `agent_histories` | транскрипты Claude, субагенты и сессии Codex **за последние 30 дней**: `files_scanned`, `files_with_hits`, `by_class`, `bytes_read`, `truncated`. Обход дома эти места пропускает из-за объёма, а копии вебхуков там находились. Всегда нижняя граница |
| `agent_configs` | `env`, `permissions.allow` и `*.bak*` конфигов Claude и Codex; отдельно `agent_configs_generic_assignment` |
| `shell_history` | история shell: файлы, `by_class`, `with_matches` |
| `storage.secrets_dirs` | каталоги хранения и их права |
| `ssh_keys`, `authorized_keys` | права и парольные фразы ключей, число записей |
| `external_access` | `gh_hosts`, `docker_registries`, `aws_profiles`, `kube_contexts` |
| `positive_controls` | `pass`/`fail` по каждому сканеру: дерево, git HEAD, история git, дом, конфиги |
| `lower_bound` | признак, что счётчики неполны (исключения и пределы обхода) |
| `timings_s` | сколько заняла каждая часть — для объяснения долгого прогона |

## Severity

- Секрет в **трекаемом файле git** или в **файле контекста агента** — **critical**.
  Приватность репозитория этого не отменяет: значение остаётся в истории навсегда.
- Секрет в доме вне трекаемых файлов и вне контекста, лежащий не в каталоге 700 с файлами
  600, — **high**. Лежит в закрытом каталоге — **medium** «не переведено на 1Password».
- Права шире `600` на файле со значением — **high**. Приватный ключ без парольной фразы,
  дающий вход на машину с `sudo`, — отдельная строка отчёта.
- Доступы к чужим порталам и организациям, которыми человек не пользуется, — **high**:
  они переживают проекты и увольнения.

## Порядок ротации в инструкции человеку

1. **Сначала ротация, потом чистка истории.** Обратный порядок оставляет рабочее значение
   в чужих копиях и бэкапах.
2. Замена значения в хранилище (1Password) и в тех местах, откуда его читают.
3. Удаление из файлов контекста — это правка существующих файлов, значит пункт инструкции,
   а не твоя работа.
4. Переписывание истории git — необратимая операция, отдельным решением человека, после
   ротации.
5. Для каждого пункта — признак готовности: «`git ls-files | xargs grep -c` по классу даёт 0».

## Бюджет: секреты не успевают в общий прогон

Замер 17.09 на машине с большим домом: раздел `secrets` в одиночку — **122 с**, из них
110 с обход дома (229 923 файла). В общем бюджете 300 с он не помещается и обрывается
с `skipped[reason=budget]`, `truncated: true`. Увидел это — **перезапусти раздел отдельно**:

```bash
python3 collect.py --only secrets --budget-seconds 900 --output ~/audit-<дата>/facts-secrets.json
```

Пока раздел не досчитан, писать «секретов не найдено» нельзя ни при каких обстоятельствах.

## Ловушки этого раздела

- **`positive_control: fail`** означает, что сканер не доказал свою работоспособность:
  его результат — `null`, а не ноль. Нельзя писать «чисто».
- **Каталог `.git` может существовать и не быть репозиторием.** Признак — ответ
  `git rev-parse --is-inside-work-tree`, а не наличие каталога.
- **Все счётчики — нижняя граница:** обход идёт с исключениями (облачные каталоги,
  `node_modules`, `.venv`) и с пределом по размеру файла.
- **Ключ хоста, совпавший с ключом локальной машины**, означает, что `Host` ведёт в саму
  машину, а не туда, куда написано. Расхождение записанного ключа с текущим — чаще упавший
  туннель или переустановленный сервер, чем атака, но принимать новый ключ молча нельзя:
  в отчёт как «требует подтверждения владельцем».
- **Расписания печатают секреты целиком.** `crontab` содержит `curl -u`, заголовки
  `Authorization:` и URL с токенами; коллектор их маскирует, но если снимаешь вывод руками —
  маскируй все три класса, иначе аудит сам станет источником утечки (так уже было).
- **Классы ловят форму, а не значение.** Самая сильная проверка — поиск по значению:
  эталон из хранилища (`~/.secrets`, `infra/secrets`, `op`), поиск по дому и истории агентов.
  В коллекторе его нет. Если делаешь руками, эталон собирай только из того, что совпало
  с классами (вебхуки, значения полей `*TOKEN`, `*KEY`, `*SECRET`, `*PASSWORD`), а не из всех
  длинных строк: «грязный» эталон на одном прогоне дал 324 файла вместо 48 настоящих.
  Выводи только пути и счётчики.
- **Копии секретов живут не только в файлах проектов:** точки отката правок
  (`~/.claude/file-history`), история промптов (`~/.claude/history.jsonl`), транскрипты,
  `~/.codex/sessions`, история PowerShell. Засветившееся там значение — тоже ротация.
- Если значение всё же попало в вывод — **не повторяй его**: «значение засветилось
  в выводе, требуется ротация».
