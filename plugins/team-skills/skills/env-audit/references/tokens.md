# Расход токенов и нагрузка инструкциями

## Что меряет коллектор

Транскрипты читаются проекцией по белому списку полей: ни текстов, ни путей, ни имён
файлов — только служебные поля, расширения правок и имена скиллов. Окно — `cleanupPeriodDays`
клиента (по умолчанию 30 дней), фактическое значение в `window_days_effective`.

| Поле | Что означает |
|---|---|
| `tokens.by_model` | суммы `input`, `output`, `cache_creation`, `cache_read` по моделям за 14 и 30 дней; usage считается один раз на пару `(message.id, requestId)` |
| `tokens.by_origin` | распределение расхода по источнику хода: человек, фоновые задачи, `/loop` |
| `tokens.subagents` | расход саб-агентов отдельным полем |
| `tokens.code_edits` | правки кодовых файлов Claude за 14 дней (по расширению) |
| `tokens.codex` | сессии Codex за те же 14 дней и вызовы `/impl`, `/fix`, `/sprint-codex`, `codex:*` |
| `instructions.start_context` | медиана стартового контекста по `entrypoint` и число исключённых сессий |
| `instructions.memory` | размеры `MEMORY.md`, каталоги памяти, `unmapped_memory_dirs[]` |
| `skills.listing_chars` | фактическая длина вложения со списком скиллов и её доля в старте |

## Единственная норма (D8)

**Кодовые задачи уходят в Codex.** Находка — Claude правит код, а Codex почти не работает:
стартовый порог — **не меньше 30 правок кодовых файлов у Claude при менее чем 3 сессиях
Codex за 14 дней**; уровень **medium**, в находке обязательно обе цифры. Порог
калибруется по прогонам. Codex не установлен или не авторизован — нарушение регламента
связки. Для профиля `codex` проверка неприменима.

Чинится **инструкцией**: подключить `/impl` и правило разделения труда в `CLAUDE.md`
проекта.

## Что идёт в отчёт цифрами, но находкой не является

- Расход по моделям и доля дорогих моделей. Выбор модели — решение человека.
- Доля расхода по источнику хода. Замер 17.09: `/loop` даёт ~0,8% расхода — норму
  по нему отменили, потому что она била мимо.
- Размер стартового контекста. Растущий старт — повод показать структуру нагрузки
  (глобальные правила + правила проекта + листинг скиллов + память), а не находка сама
  по себе.

## Нормы нагрузки инструкциями

- `MEMORY.md` — **≤ 200 строк и ≤ 25 000 байт**: при загрузке индекс обрезается, и всё,
  что за порогом, агент просто не видит. Превышение — находка, чинится сжатием индекса
  (клинап) без потери указателей.
- Память одного проекта в нескольких каталогах — находка **только по сопоставленным
  каталогам**; `unmapped_memory_dirs[]` — кандидаты, требующие вопроса человеку.
  Сведение памяти аудит не делает: это перенос файлов, пункт инструкции.
- Длинный листинг скиллов — повод отключить неиспользуемые user/project-скиллы
  (`cleanup.md`) и перевести свои описания на английский; описания скиллов обменника
  правятся в обменнике, а не на машине.

## Ловушки

- **Стартовый контекст считается по первому ответу сессии.** Сессия, продолженная после
  компакта, несёт историю в первом же ответе; такие сессии исключаются из медианы, иначе
  «стартовый контекст» вырастет до сотен тысяч токенов.
- **Сессии Codex считаются по последней активности**, а не по дате создания файла:
  иначе долгая сессия, начатая до окна, не попадёт в счёт.
- **Расход Codex** — последний максимальный `total_token_usage` на сессию, не сумма
  событий: события кумулятивные, сумма завышает в разы.
- Источник хода у старых клиентов не записан — такие ходы считаются человеческими
  и выводятся отдельным счётчиком.
