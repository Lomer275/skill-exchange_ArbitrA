# Архитектура и структура — дайджест для аудитора

Полные правила, пороги и калибровка — в справочнике проекта
(`S55_architecture_check_reference.md`). Здесь — то, что нужно, чтобы прочитать
`sections.architecture` и не выдумать находок.

## Пять проверок

| # | Проверка | О чём |
|---|---|---|
| 1 | **Тип проекта** | application (service, cron-agent, client-server, multi-app, plugin-in-host), integration-scripts, mixed, library, docs. Тип выбирает рубрику |
| 2 | **Живой код против git** | исполняется ли то, чего нет в репозитории: `rule_inputs.A1, A2, A3, A4, I1, I2, I3` |
| 3 | **Документы против кода** | ссылки в документах на несуществующие пути, свежесть, покрытие: `A5–A8` |
| 4 | **Структура кода приложений** (Python, `ast`) | циклы, «god», дубли, сироты, каналы, слои: `A9–A21`, «луковица» |
| 5 | **Гигиена — для всех типов** | `H1–H7`, для скриптов `I5–I15` |

Секреты и ПДн (`S1–S4`, `I4`) считает раздел `secrets` — находка выносится **один раз**,
из него, а не из архитектуры.

## Уровни

- **critical** — только `S2`/`I4`, когда значение лежит в трекаемом файле git или в файле
  контекста агента (`CLAUDE.md`, `AGENTS.md`, память, скиллы).
- **high** — только: `A1`, `A2`, `I1`, `I2`, `I3` («код исполняется не из git»); `A17`,
  когда цель runtime лежит в `.gitignore`; `S1`; `S2`/`I4` вне контекста и вне трекаемых
  файлов; `S3` (ПДн).
- **medium** — всё остальное содержательное: `A3`, `A4`, `A17` при цели в `.dockerignore`,
  **все структурные** (`A9–A21`, `I5–I7`), `I4` при хранении в каталоге 700 с файлами 600.
  Потолок структурных находок — medium, выше он не поднимается.
- **low / info** — косметика и метрики.

## Потолок и отбор

Не больше **8 находок на проект** (в `multi-app` — на весь проект). Порядок отбора:
severity → ops → секреты и ПДн → схема → документы → структура → гигиена.
Слияния: `I1 + I3`; `A14(1) + A15 + A5` по одному модулю; `A6 + A5`;
`A17 + runtime → tools`; `A5 no_secrets + S2`. Low при переполнении переезжает
в гигиену одной строкой.

## Формат находки

```
[ARCH-N] <severity> · <класс> · <что сломано, одной фразой>
Доказательство: <число и путь> (дерево: <tree_id> @ <sha>, правило <ID>)
Почему это вред: <одна фраза>
Против ложных срабатываний: <ответ на четыре вопроса или факт закрытого списка>
[только секреты] liveness: не установлена | отозван (<источник>); user_id: <id>
Что сделать: <одно действие>
```

## Порядок работы с разделом

1. **Сверить тип:** прочитать `decision_trace`. Тип противоречит `runtime.anchors` —
   находок не выносить, записать расхождение.
2. **Проверить, какое дерево меряли** (`tree.analysed`): живой юнит с кодом в замыкании →
   рабочее дерево; shell-замыкание или неживой отставший чекаут → архив; иначе
   остановиться и сообщить. `vcs.present = null` и `live_units = null` читаются как
   «не проверено», а не «нет».
3. **Пройти `rule_inputs`** в порядке: ворота → A1–A4 → A5–A8 → A9–A21 → H (для скриптов I).
4. **До назначения severity прочитать файлы доказательства.** Числа не пересчитывать;
   противоречие с кодом — в `errors`.
5. **Слияние и потолок**, затем `blind_spots` и `skipped` — в «Не проверено». Слово «чисто»
   для них не использовать.

## Что находкой не является (частые ложные срабатывания)

- Наличие каталога `.git` без репозитория; определение типа проекта по текстам документов,
  байтам markdown или отсутствию `Dockerfile`.
- `TYPE_CHECKING`-импорт как цикл; SCC пакетов без цикла модулей; `ready()` и
  `__init__ ↔ подмодуль`; реэкспорт в `__init__`.
- Крупный файл сам по себе: `models.py`, `settings.py`, реестры, промпты, данные, стили
  XAML. Размер не связывают с инцидентами без доказательства.
- Нарушение слоёв там, где слои не объявлены; `application → django`, сервисы → ORM/DTO;
  оркестратор отдельных адаптеров; composition root, связывающий адаптеры.
- Похожесть на соседний репозиторий (это «общее происхождение»); копии документов
  и сгенерированные файлы; хелперы в одноразовых скриптах.
- Задачи внутри спецификаций; ссылки на пути, помеченные удалёнными; межрепозиторные
  ссылки, разрешимые на удалённой ветке; `CLAUDE.md` пакетов и `AGENTS.md`-указатель.
- Фейковые значения секретов по сериям, заглушки и фикстуры; `${VAR:-placeholder}`
  при обязательном `env_file`; числовые идентификаторы; ИНН из 10 цифр.
- Лог-редирект, `cd` и `EnvironmentFile` не делают юнит живым; `__init__.py` и файлы
  меньше 20 строк не считаются дублями-сиротами; автообнаружение Django — не сироты.
- Меньше 10 модулей или рёбер — это справка, а не структура.

**Не-Python языки** (PHP, JS/TS, C#) в v3.0 дают только метрики: размер, расположение,
дубли, точки входа. Графы зависимостей и контракты между языками — вне скоупа,
находок не дают.
