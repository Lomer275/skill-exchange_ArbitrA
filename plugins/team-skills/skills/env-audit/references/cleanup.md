# Клинап — что чинится после «да», а что только планом

Инструмент: `cleanup.py`. Он **не решает**, что чинить: он показывает конкретный дифф,
а решение принимает человек. Аудит применяет правки только после согласия №2.

## Порядок

```bash
D=~/audit-$(date +%F)/cleanup
python3 cleanup.py plan   --facts ~/audit-$(date +%F)/facts.json --out-dir $D
# прочитать $D/plan.json, выставить "selected" по своему решению
python3 cleanup.py render --plan $D          # пересобрать дифф
# показать человеку $D/plan.diff целиком → получить «да»
python3 cleanup.py apply  --plan $D --confirmed
python3 cleanup.py verify --plan $D
# если стало хуже:
python3 cleanup.py rollback --plan $D --confirmed
```

Каталог плана создаётся с правами 700, файлы — 600. Без `--confirmed` `apply`
и `rollback` ничего не делают и выходят с кодом 2.

## Что попадает в список «после да»

| Вид | Когда предлагается |
|---|---|
| раздел `CLAUDE.md` → гайд | раздел больше ~1,5 КБ; тело переезжает в `docs/4. <П>-guides/<имя>.md`, в инструкции остаётся ссылка |
| шаг записи в канон в проектном `close` | разрешённый `close` пишет журнал и не пишет канон |
| то же в разделе `/close` в `AGENTS.md` | для Codex, вне управляемого блока |
| пометка архивного HANDOFF | у неканонических файлов состояния первой строкой появляется «Архив. Текущее состояние — в …» |
| сжатие индекса `MEMORY.md` | индекс за порогом строк или байт; множество ссылок до и после обязано совпасть |
| `skillOverrides: off` | user/project-скилл вне защищённого списка без вызовов за окно |
| снятие `off` | обязательный скилл оказался выключен |

**Защищённый список — никогда не кандидат на выключение:** десять обязательных скиллов,
все скиллы superpowers, `env-audit`, скиллы, на которые ссылаются `CLAUDE.md`/`AGENTS.md`
проекта. Скиллы плагина по одному не выключаются вовсе — это делается в обменнике.

## Блокировки (пункт не применяется)

`secret` — в переносимом разделе или в новом тексте нашлись значения (дифф такого пункта
не пишется, в описании только класс) · `team_context` — правка задевает строки между
маркерами управляемого блока · `target_exists` — файл гайда уже есть · `cannot_fit` —
индекс не укладывается в пределы · `secret_in_settings` — в `env` или `permissions.allow`
нашлись значения, файл не копируется и не правится · `plugin_close` — `close` из плагина
(правка в обменнике) · `no_canon` — канона HANDOFF нет.

## Что не делает даже после «да» (только пункт инструкции)

Такие пункты перечислены в `manual[]` плана — с классом и числом, без путей и значений
(`context_values`, `tracked_values`, разъехавшаяся память, код вне git, старые журналы).

Сведение разъехавшейся памяти · история git, ротация и перенос секретов · любые действия
наружу и на других машинах · **удаление файлов**. Неканонические файлы состояния остаются
на месте и только помечаются архивными: удаление журнала запрещено.

## Правила применения

- **Бэкап каждого изменяемого файла** — в `~/audit-<дата>/backup/<исходный путь>`
  (каталог 700, файлы 600). Путь бэкапа идёт в отчёт, срок удаления (+14 дней) —
  в инструкцию. Коллектор исключает этот каталог из сканов.
- Файл изменился между `plan` и `apply` — пункт помечается `stale` и пропускается.
  Аудит не перезаписывает то, чего не видел в момент планирования.
- Правка `settings.json` ради `skillOverrides` — **единственное** исключение из правила
  «файл прав не правь», и только этот ключ.
- Содержимое между маркерами управляемого блока не трогается никогда;
  `agents-context apply` — только после прочитанного `--dry-run` (стоп, если удаляются
  строки, которых больше нигде нет, или маркеры повреждены).
- После применения — повторный сбор фактов и сравнение «до/после» (`verify`),
  а если правился `CLAUDE.md` или `AGENTS.md` — ещё и поведенческая проверка стоп-линий.
