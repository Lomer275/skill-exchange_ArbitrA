# env-audit

Аудит рабочего окружения человека силами его же агента. Ничего не чинит — снимает факты,
сверяет с командным стандартом и отдаёт отчёт с планом правок.

## Зачем

Жалобы «агент выдумывает», «теряет нить», «не помнит вчерашнее» почти всегда имеют
проверяемую причину, и чаще всего она текстовая: инструкция объявляет доступными скиллы
и знания, которых агент не загружает, — модель действует так, будто они есть, и достраивает
недостающее вымыслом. Скилл ищет такие расхождения между заявленным и фактическим,
а заодно смотрит на секреты, ресурсы машины и способ работы.

## Что проверяет

- **AI-окружение** — глобальный слой контекста обоих агентов, инструкции проекта,
  скиллы (заявленные против загружаемых), память и её свежесть, MCP, разрешения, размер сессий.
- **Секреты и доступы** — что попадает в контекст сессии, насколько широко разошлось,
  права на хранилище, ssh-ключи и куда на самом деле ведут хосты.
- **Ресурсы** — диск, память, лимиты cgroup, слепые зоны без root.
- **Процессы** — преемственность между сессиями, git-гигиена, бэкапы, расхождение
  отчёта с фактом.

## Как запустить

```
/env-audit
```

Дальше агент читает `audit-brief.md` и идёт по фазам. Прогон — 60–90 минут.

## Что на выходе

- `~/audit-<дата>/REPORT.md` — находки по уровням серьёзности, каждая с выводом команды,
  раздел «что в порядке», раздел «слепые зоны» и план правок с обоснованным порядком.
- `~/audit-<дата>/FACTS.txt` — сырые выводы команд, доказательная база.
- Короткая сводка в чат: критичное, что это значит, первое действие.

## Границы

Скилл **ничего не меняет** и не выполняет собственный план — правки делает человек отдельным
заходом. Значения секретов не печатаются нигде: только имена ключей и счётчики вхождений.
Основной тракт команд — Linux; для Windows в брифе есть приложение с эквивалентами
на PowerShell.
