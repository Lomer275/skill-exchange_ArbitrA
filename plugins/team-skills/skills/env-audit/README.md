# env-audit

Приёмка рабочего места силами агента самого человека: сначала полный снимок фактов,
потом наладка в узких границах, потом отчёт с планом на остальное.

## Зачем

Жалобы «агент выдумывает», «теряет нить», «не помнит вчерашнее» почти всегда имеют
проверяемую причину, и чаще всего она текстовая: инструкция объявляет доступными скиллы
и знания, которых агент не загружает, — модель действует так, будто они есть, и достраивает
недостающее вымыслом. Отсюда выросло остальное: если уж агент осматривает рабочее место,
пусть проверит его целиком и доведёт до общего стандарта.

## Одиннадцать регламентов, которые проверяются всегда

| # | Регламент | Чинит сам |
|---|---|---|
| Р1 | Обменник скиллов подключён и обновляется | да |
| Р2 | Структура документации в каждом проекте | да, скелет |
| Р3 | Десять обязательных скиллов на месте | да |
| Р4 | GitHub: авторизация и привязка всех проектов | нет |
| Р5 | Три уровня правил и памяти Claude | да |
| Р6 | Связка Claude × Codex собрана | да |
| Р7 | Docker у сервисных проектов | нет |
| Р8 | Регламент Битрикса записан в память | да |
| Р9 | Принципы работы записаны в память | да |
| Р10 | Знакомство с человеком записано | да |
| Р11 | Плагин superpowers установлен | да |

Сквозным порядком проверяются секреты в файлах контекста, стоп-линии, ресурсы машины
(диск, память, лимиты) и рабочие процессы — преемственность между сессиями, git-гигиена,
бэкапы, расхождение отчёта с фактом.

## Как запустить

```
/env-audit
```

Прогон — полтора-два часа. Агент читает `audit-brief.md` и идёт по фазам: A–E снимок
окружения, F проекты и документация, G знакомство с человеком, H разрешённые правки,
затем критический проход по собственным находкам и отчёт.

## Что на выходе

- `~/audit-<дата>/REPORT.md` — находки по уровням серьёзности, каждая с выводом команды;
  таблица одиннадцати регламентов; разделы «что в порядке» и «слепые зоны»; список
  выполненных правок «было → стало»; план на остальное с обоснованным порядком.
- `~/audit-<дата>/FACTS.txt` — сырые выводы команд, доказательная база.
- Короткая сводка в чат: критичное, что это значит, первое действие.

## Границы

**Сначала измерение, потом правки** — иначе картина «как было» теряется безвозвратно.
Правки только из закрытого белого списка: поставить плагины, применить общий контекст,
развернуть память и записать карточки, создать недостающие каталоги документации.
Всё остальное — удаление, перемещение, переписывание, история git, секреты, любые действия
наружу — только планом для человека.

Значения секретов не печатаются нигде: имена ключей и счётчики вхождений.
Основной тракт команд — Linux; для Windows есть приложение с эквивалентами на PowerShell
и списком проверок, которые там неприменимы.
