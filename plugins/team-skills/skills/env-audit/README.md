# env-audit

Приёмка рабочего места силами агента самого человека: сначала полный снимок фактов,
потом наладка в узких границах, потом отчёт с планом на остальное.

## Зачем

Жалобы «агент выдумывает», «теряет нить», «не помнит вчерашнее» почти всегда имеют
проверяемую причину, и чаще всего она текстовая: инструкция объявляет доступными скиллы
и знания, которых агент не загружает, — модель действует так, будто они есть, и достраивает
недостающее вымыслом. Отсюда выросло остальное: если уж агент осматривает рабочее место,
пусть проверит его целиком и доведёт до общего стандарта.

## Одиннадцать регламентов, которые проверяются всегда

| # | Регламент | Чинит сам |
|---|---|---|
| Р1 | Обменник скиллов подключён и обновляется | да |
| Р2 | Структура документации в каждом проекте | да, скелет |
| Р3 | Десять обязательных скиллов на месте | да |
| Р4 | GitHub: авторизация и привязка всех проектов | нет |
| Р5 | Три уровня правил и памяти Claude | да |
| Р6 | Связка Claude × Codex собрана | да |
| Р7 | Docker у сервисных проектов | нет |
| Р8 | Регламент Битрикса записан в память | да |
| Р9 | Принципы работы записаны в память | да |
| Р10 | Знакомство с человеком записано | да |
| Р11 | Плагин superpowers установлен | да |

Сквозным порядком проверяются секреты (файлы контекста, трекаемые файлы git, дом, ключи,
доступы) и хранение их в 1Password, сетевая досягаемость, расход токенов и разделение труда
с Codex, архитектура проектов, ресурсы машины (диск, память, лимиты) и рабочие процессы —
преемственность между сессиями, git-гигиена, бэкапы, расхождение отчёта с фактом.

## Как запустить

```
/env-audit
```

Прогон — час-полтора. Одно согласие на читающие действия, дальше `collect.py` снимает
все факты в один JSON, агент их толкует по короткому брифу (`audit-brief.md`, до 20 КБ)
и открывает справочник из `references/` только по той теме, где что-то нашлось.

Дальше — знакомство с человеком, план, **показанный дифф клинапа и второе «да»**
на его применение, **третье «да»** на проверку по факту в песочнице (с оценкой расхода),
критический проход по собственным находкам и отчёт.

Коллектор можно запустить и на другой машине того же человека, ничего там не записывая:

```bash
python3 collect.py --bundle | ssh <хост> python3 - --expect-user <имя> --output -
```

## Что на выходе

- `~/audit-<дата>/REPORT.md` — находки по уровням (critical / high / medium / low), каждая
  с доказательством; таблица одиннадцати регламентов; разделы «что в порядке» и «слепые
  зоны»; список выполненных правок «было → стало»; инструкция человеку на остальное.
- `~/audit-<дата>/facts.json` — все снятые факты, доказательная база.
- `~/audit-<дата>/cleanup/` — план правок, дифф и бэкапы применённого.
- Вердикты песочницы: пишет ли закрытие дня в канонический HANDOFF и CHANGELOG.
- Короткая сводка в чат: критичное, что это значит, первое действие.

## Границы

**Сначала измерение, потом правки** — иначе картина «как было» теряется безвозвратно.
Правки только из закрытого белого списка: поставить плагины, применить общий контекст,
развернуть память и записать карточки, создать недостающие каталоги документации,
и отдельно — дифф клинапа, применяемый после явного «да», с бэкапом каждого файла.
Всё остальное — удаление, перемещение, переписывание, история git, секреты, любые действия
наружу — только инструкцией для человека.

Значения секретов не печатаются нигде: имена ключей и счётчики вхождений; перед показом
и записью каждый файл прогоняется через `collect.py --scan-file`. Вход по ssh на прод
и чужие машины не выполняется ни при каких условиях.

Коллектор рассчитан на Linux и python3.10 из стандартной библиотеки; под Windows он
не запускается — там аудит идёт вручную по `references/windows.md`.
