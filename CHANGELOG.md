# История выпусков

## 2.3.0 — 26 ноября 2026

- `github-task` обновлён с `1.0.0` до `1.1.0`: проверка учётки и scopes Projects, выбор токена без смены активной учётки. Подтверждение новых прав выполняет человек.
- Добавлены передача и продолжение ветки: черновой PR с обновляемым паспортом, комментарий issue, один согласованный Assignee и продолжение той же ветки без force-push. Push/PR подчиняются разрешениям целевого проекта.
- Имя ветки берётся из проекта; при отсутствии правила предлагается `<type>/<issue>-<slug>`.
- Версия плагина `team-skills` — `2.3.0`; каталог перегенерирован.

## 2.0.0 — 5 ноября 2026

Это выпуск с изменениями совместимости для команд, которые устанавливают каталог в собственные репозитории.

### Что изменилось

- Собственные одноимённые навыки проекта и пользователя имеют приоритет. Обязательный Step 0 проверяет их до любых действий; навык каталога выбирается явно через `/team-skills:<имя>` либо при отсутствии собственного. Исключение — внутренний `codex-worker`.
- Пути документов и команды проекта задаёт `.claude/team-skills.json` версии 1. Без профиля или нужных ключей теперь останавливаются `close`, `intro`, `accept`, `spec-writer`, `spec-brainstorm`, `sprint`, `sprint-codex` и `auto-pilot`. Профиль создаёт `init_dev`. Остальные навыки работают без профиля и сообщают о пропущенном поиске проектных документов. Единственное умолчание команды — `commands.push`: `/team-skills:safe-push`.
- Модель Codex и effort задаются явно: аргументы вызова → `.claude/codex.json` с полями `model` и `effort` → `gpt-6-luna` / `medium`. Настройки модели из `~/.codex/config.toml` больше не используются. Пробы и прогрев используют выбранную модель с effort `low`.
- Коммит, push, merge, создание/мерж PR и удаление веток/worktree требуют явного «да» человека в текущем диалоге на конкретные файлы и действие. Согласие на commit не разрешает push. `--yes`, cron, разрешения HANDOFF/конфига и TG-согласование плана не заменяют это согласие. Автопилот и безголовые запуски заканчивают подготовку статусом `ready to commit` (или `ready for review/commit`), показывают файлы и предлагаемое сообщение, уведомляют через настроенный канал и не публикуют изменения.
- В `bitrix24-developer` введена обязательная политика записи: сначала песочница, если она есть; запись в production — через объявленный проектом маршрут либо после явного согласия на методы, ID и изменения «до → после». Массовые операции требуют предварительного dry run и подтверждения полного списка; write-batch использует `halt: 1`, удаление и остановка процессов требуют поэлементного подтверждения. `BITRIX_WEBHOOK` поступает из хранилища секретов в окружение; git-игнорируемый env-файл заполняют в редакторе. Значение нельзя печатать, переносить в чат/навык/git или оставлять в истории shell.

### Что сделать при обновлении

1. Создайте `.claude/team-skills.json` по [справочнику профиля](docs/team-skills-profile.md) либо запустите `/team-skills:init_dev`. Укажите реальные пути вашего репозитория и ключи, необходимые выбранным навыкам.
2. При желании задайте в `.claude/codex.json` поля `model` и `effort`, например `{"model": "gpt-6-luna", "effort": "medium"}`. Без них действует то же встроенное умолчание.
3. Обновите marketplace: `/plugin marketplace update skill-exchange`, затем плагин: `/plugin update team-skills@skill-exchange`. Перезапустите Claude Code.
4. Просмотрите **все** версии в `~/.claude/plugins/cache/skill-exchange/team-skills/` и убедитесь, что появился каталог `2.0.0` с соответствующей версией в `.claude-plugin/plugin.json`. Старые каталоги кэша не удаляются автоматически; наличие старой версии рядом не означает, что обновление не состоялось. Если `2.0.0` отсутствует, проверьте результат обновления и установленный marketplace.
